# 제이퍼 계산기 노트(티스토리) 원고 규칙 v1 초안

작성 2026-11-19. 블로그 주소 https://jptcalc.tistory.com
네이버 규칙(naverblog-rules.md v7)과 별개 문서다. 숫자 검증 절차만 네이버 §9를 그대로 가져오고, 나머지는 구글 기준으로 다시 정했다.

## 0. 목적이 다르다

네이버 블로그: 네이버 검색 + 애드포스트 조회수.
티스토리: **구글 색인 → 애드센스 승인**. 독자는 구글에서 검색해 들어온 사람이다.
그래서 네이버 규칙 중 네이버 전용인 것(제목 앞 12자, 하이픈 1회, 2,700~2,900자, 캡처 4장, 댓글 유도, 표 금지)은 쓰지 않는다.

## 1. 발행

1. **주 5편, 월~금**(11/19 사용자 확정, 자동 발행 가능해져서 주3에서 상향). 첫 글 t1은 11/20(금), 주5는 11/23(월)부터. 요일별 카테고리 고정: 월 연봉·퇴직 / 화 대출·부동산 / 수 세금·연말정산 / 목 건강 수치 / 금 날짜·나이(시즌 주제가 크면 바꿀 수 있음).
2. 예약 발행 08:00 고정. 예약 등록은 Claude가 윈도우 크롬 자동화로 대행(11/19 t1 성공, 본문은 tinymce.activeEditor.setContent).
3. 한 주치 3편을 미리 작성해 전달, 사용자가 한 번에 예약.
4. 카테고리 5개: 세금·연말정산 / 연봉·퇴직 / 대출·부동산 / 날짜·나이 / 건강 수치. 같은 카테고리 연속 금지.
5. 광고(수익 메뉴) 연결 금지. 애드센스 신청 기준은 공개 글 20편 + 구글 색인 15편 + 소개 페이지(완료).

## 2. 주제 고르기와 중복 판정 (가장 중요)

**11/19 사용자 지적으로 수정: 같은 주제·검색어를 피할 필요는 없다. 피할 것은 "같은 글"이다.**
- jptcalc.kr과 jptcalc.tistory.com은 구글에게 서로 다른 사이트다. 같은 사이트 안의 글 두 개가 한 자리를 다투는 것과 달리, 다른 사이트는 검색 결과 두 칸을 각각 차지할 수 있다. 게다가 jptcalc.kr은 지금 구글 노출이 거의 없어서(11/19 GSC 90일 검색어 = site: 자기검색뿐) 다툴 자리도 없다.
- 위험한 건 **베껴 쓰기·문장만 바꿔 쓰기**다. 구글은 거의 같은 글을 중복으로 보고 하나만 보여 주며, 대량으로 하면 스팸 정책의 "대규모 콘텐츠 남용"에 걸린다.

그래서 기준은 이렇다.
1. **사이트 블로그·네이버 블로그와 같은 주제·검색어 허용.** 단 각도(질문), 숫자 사례, 표 구성, 문장을 새로 잡는다. 기존 글을 열어 놓고 고쳐 쓰지 않는다.
2. 같은 검색어면 기존 글이 쓴 **기준 금액·조건은 피한다**(네이버 §3 역산 방식). 예: 사이트가 "3억 30년 원리금 vs 원금"이면 티스토리는 "3억을 금리별로".
3. **티스토리 자기 글끼리**는 네이버 §3처럼 축을 역산해 겹치지 않게 한다.

우선 고를 주제
0. **피할 주제(11/19 t1 반성)**: 노무·제도 설명형(연장근로수당, 주휴수당, 실업급여 등)은 고용노동부·사람인·노무사 사이트와 AI 요약이 구글 상위를 잡고 있어 순위 진입이 어렵다. 쓰더라도 후순위.
1. **비교형 우선**: "금액별·조건별 표"처럼 계산기로만 만들 수 있는 숫자 비교(대출 금리별 월 상환액, 연봉 구간별 실수령 차이, 차값별 취득세 등). 구매·지출 직전 판단형(네이버 v7 §12)과 겹치면 더 좋다.
2. 검색량이 크고 시즌이 다가오는 주제(사이트에 글이 있어도 각도가 다르면 된다)
3. 사람이 실제로 묻는 구체적 질문형 검색어 ("월급 300 실수령", "퇴직금 1년 미만" 같은 형태)
4. 검색량은 키워드사운드(네이버 수치)를 참고하되, 구글은 별도 수치가 없으니 jptcalc.kr GSC 검색어(노출은 있는데 맞는 글이 없는 것)를 함께 본다

## 3. 제목

1. 검색어를 앞쪽에, 자연스러운 문장으로. 공백 포함 42자 이하. 첫 쉼표 앞 = 검색어, 뒤 = 결론 숫자(대표이미지에 그대로 들어간다).
2. 답(결과 숫자)을 제목에 써도 된다. 구글은 제목과 본문이 일치하는지를 본다.
3. 낚시형 반전 문구, 과장 금지.
4. 연도는 그해 기준이 실제로 적용되는 글에만 넣는다.

## 4. 본문

1. **분량 목표 없음.** 질문에 답하는 데 필요한 만큼. 대체로 1,500~3,500자 범위에 들어온다. 늘리려고 쓰는 문단 금지.
2. 첫 3~4줄 안에 질문의 답(핵심 숫자)을 준다.
3. 구조: 제목(H2) 3~5개, 필요하면 표 1~2개. 네이버와 달리 **표 사용 권장**.
4. **"직접 넣어 본 숫자"가 핵심.** 제이퍼 계산기에 실제로 넣은 사례 2~4개. 이게 다른 검색 결과에 없는 정보다.
5. 기준 표기: 글 끝 회색 한 줄 "기준: 2026년 ○○ 고시 · 확인일 2026-11-○○". 맨 위에 두면 티스토리 목록 요약이 그 줄로 시작한다(11/20).
6. 마지막에 "확인할 것" 3~5개와 출처 기관명(링크는 필요할 때만).
7. 문체: 해요체. em dash, 마크다운 볼드 기호 금지. 이전 글을 번호·날짜로 언급 금지. 계산기 화면 묘사(색·버튼 위치) 금지.
8. 같은 틀 반복 금지: 도입 유형과 소제목 이름을 글마다 바꾼다.
9. **글쓴이 한 단락**(마지막 면책 문구 바로 위): "글쓴이 제이퍼" + 계산기를 직접 만들고 운영한다는 사실 + 숫자는 계산기에 직접 넣어 확인했다는 문장 + `https://jptcalc.tistory.com/page/about` 링크. 문장은 글마다 조금씩 바꾼다.
10. **간격**: 오디세이 스킨은 문단 간격 0, 인라인 margin은 무시된다. 문단·표·목록 뒤(다음이 문단일 때)에 `<p data-ke-size="size16">&nbsp;</p>` 스페이서. 표는 4칸 이하, 숫자 칸 `white-space:nowrap`.

## 5. 링크

1. 제이퍼 계산기 링크 글당 1~2개. 본문 중간(사례 직후) 1개 + 끝 1개.
2. 주소는 `https://www.jptcalc.kr/...`(www 없는 주소는 301로 넘어감, 11/19 확인). UTM: `?utm_source=tistory&utm_medium=blog&utm_campaign=t{N}` (GA4에서 네이버와 구분).
3. 프리필 링크 금지(네이버 §7과 같은 이유).
4. 관련 티스토리 글 내부 링크는 글이 쌓인 뒤 1개까지.
5. 폼다·부모혜택·DueGuard 링크 넣지 않는다.

## 6. 이미지

1. **계산기 캡처 1장 필수**(직접 해 봤다는 증거). 본문 사례 하나를 실제 jptcalc.kr 계산기에 넣은 입력+결과 화면. 헤드리스 크롬으로 찍는다(`cap.mjs` + `caps/setup/tNNN.js`, /tistory 스킬 6단계). 캡처의 합계가 본문 숫자와 같아야 한다.
2. 캡처 아래 회색 한 줄 설명. 대체텍스트(alt)에 "월 통상임금 350만원 가산수당 계산 결과 569,378원"처럼 내용을 쓴다.
3. **대표이미지(11/20 확정)**: 카테고리마다 배경색·아이콘 고정, 글자는 그 글 제목만(쉼표 앞 크게·뒤 노랗게). `python3 make_thumb.py thumbs/tNNN.jpg "카테고리" "제목"`. 연봉·퇴직=남색·₩, 대출·부동산=청록·집, 세금·연말정산=보라·계산기, 건강 수치=자주·하트, 날짜·나이=초록·달력(새 카테고리는 TPL 한 줄 추가). 같은 이미지를 **본문 맨 위**(`<p>[[TOPIMG]]</p>`)에도 넣는다. 스킨 CSS로 글 상단은 흰 바탕·검은 제목(정보형 블로그 방식, 띠 없음, `skin/white-header.css`).
4. 업로드는 크롬 자동화(`/tistory-publish`): 본문 첫 줄 `[[TOPIMG]]`에 대표이미지, `[[CAPTURE1]]` 표시 문단을 두고 에디터 사진 업로드로 그 자리에 넣은 뒤 표시 삭제, 대표이미지는 발행 레이어 file input.

## 7. 숫자 검증

네이버 규칙 §9를 그대로 따른다. 계산기 JS 포팅 → 페이지 예시표와 원 단위 대조 → 표시 포맷 함수 확인 → 입력 단위 확인. 검증 없이 본문을 쓰지 않는다. ★ 항목(외부 고시)은 원문 확인.

## 10. 자동 발행 운영 규칙 (11/19 신설, Claude가 크롬 자동화로 직접 예약)

### 10-1. 언제 하나
1. 사용자가 "티스토리"라고 하면 **다음 주 월~금 5편을 한 번에** 쓰고 예약까지 건다(주 1회 묶음). 사용자가 말하지 않으면 먼저 꺼내지 않는다.
2. 예약은 발행 시각보다 **최소 하루 앞서** 건다. 본문 이미지 검토(불법촬영물 필터)가 오래 걸릴 수 있고, 사용자가 확인할 시간이 필요하다.

### 10-2. Claude가 해도 되는 것 / 안 되는 것
해도 됨
1. 새 글 작성 → **예약 발행만**(08:00, 공개).
2. 아직 발행 전인 **내가 건 예약 글**의 본문·이미지 수정.
3. 본문 이미지·대표이미지 업로드.

하면 안 됨 (사용자가 그때 명시적으로 시킬 때만)
1. 즉시 발행. 예약 설정이 안 되면 임시저장으로 멈추고 보고한다.
2. 이미 발행된 글 수정·삭제·비공개 전환.
3. 블로그 설정·스킨·메뉴·카테고리·플러그인 변경, 수익(광고) 메뉴 연결.
4. 댓글·방명록 작성, 다른 블로그 구독·공감.

### 10-3. 한 편 처리 순서 (1~2·6은 `/tistory`, 3~5는 `/tistory-publish`)
1. 주제 선정(§2) → 숫자 검증(§7) → 본문 HTML(`tistory/posts/tNNN-*.html`)
2. 계산기 캡처(`tistory/caps/tNNN-cap.jpg`, 합계가 본문과 같은지 확인) + 대표이미지(`tistory/thumbs/tNNN.jpg`)
3. 크롬 자동화 **1회 호출로 그 주 5편 모두**: 새 글 → 카테고리·제목 → setContent → `[[CAPTURE1]]` 자리에 캡처 업로드·alt → 태그 → 완료 → 예약·공개·대표이미지 → 저장
4. 확인: 글 관리에 `[예약]` 날짜·시각, 각 글 화면 캡처를 내가 직접 보고 깨진 곳 없는지
5. **작업 끝에 자기가 연 탭을 모두 닫는다.** 프롬프트는 영어, 한글 데이터는 파일로(Read).
6. `ledger.tsv`에 기록(날짜·번호·글번호·카테고리·제목·계산기·축).

### 10-4. 사용자에게 보고
**구조 확정(11/19): 예약은 Claude, 확인은 사용자.** 사전 승인 단계 없음.
예약이 끝나면 한 번에 보고한다: 날짜별 제목, 글 주소, 주제 고른 이유 한 줄, 확인할 점. 사용자는 글 관리에서 보고 고칠 곳을 말한다. 사용자가 편집 화면에서 직접 저장하면 예약이 풀릴 수 있으니 고칠 곳은 말로 받는다.

### 10-5. 발행 전 점검
1. 발행 전날 또는 다음 묶음 작업 때, 예약 글 화면에서 본문 이미지가 "검토중" 자리표시로 남아 있는지 확인. 남아 있으면 다시 올리고, 그래도 안 되면 캡처를 빼고 발행되게 한다(회색 칸 노출 금지).
2. 실패하면 숨기지 않고 그대로 보고한다.

## 11. 글 품질: AI 티 금지·틀 반복 금지 (11/19 사용자 요구, 최우선)

목표는 "검색해서 들어온 사람이 다른 글을 더 안 찾아봐도 되는 글"이다. 구글 도움되는 콘텐츠 기준의 질문(직접 해 본 경험이 보이나, 다른 데 없는 정보가 있나, 다 읽고 만족하나)에 예라고 답할 수 있어야 한다.

### 11-1. 품질의 핵심 (이게 없으면 쓰지 않는다)
1. **우리만 가진 숫자**: 계산기로 직접 뽑은 표·사례. 남의 글에 있는 숫자를 옮기지 않는다.
2. **판단이 들어간 문장**: 숫자를 나열하고 끝내지 않는다. "그래서 이 구간에서는 A가 낫다", "여기서부터는 늘려도 의미가 작다"처럼 숫자를 읽어 준다. 글마다 최소 2곳.
3. **사람들이 실제로 틀리는 지점**: 흔한 오해 1개 이상을 숫자로 바로잡는다(t1의 "토요일은 대개 휴일근로가 아니다"처럼).
4. **확인한 사실만**: 법령·고시 수치는 원문 확인, 계산은 계산기 포팅 검증. 모르는 건 쓰지 않는다.

### 11-2. AI 티 나는 표현 (금지)
- 인사·예고·마무리 상투어: "안녕하세요", "~에 대해 알아보겠습니다", "~을 정리해 보겠습니다", "지금부터", "이번 글에서는", "마무리하며", "도움이 되셨길 바랍니다", "참고하시기 바랍니다", "궁금하셨던 분들"
- 빈 강조: "중요합니다", "필수적입니다", "꼭 알아두세요", "핵심은 이겁니다", "답은 간단합니다", "결론적으로", "요약하자면", "한마디로"
- 부풀린 수식어: "다양한", "효과적인", "꼼꼼히", "현명한", "체계적인", "완벽 정리", "총정리", "A to Z"
- 두루뭉술한 권유: "~하는 것이 좋습니다"가 글 전체 2회 초과 금지. 대신 조건과 숫자로 말한다.
- 기계적 대칭: 항목 3개짜리 목록만 반복, 모든 소제목 아래 문단 길이가 비슷한 것, 모든 목록 항목이 "굵은 제목. 설명" 형태로 같은 것.
- em dash(—), 이모지 남발(👉 링크 표시 외 금지), 느낌표.
- 영어식 번역투: "~에 있어서", "~를 통해", "~하는 데 있어", "가지고 있다"(소유 아닌 것).

### 11-3. 틀 반복 금지 (글마다 달라야 하는 것)
매 편 작성 전에 `ledger.tsv`의 직전 4편 구성을 확인하고 아래 중 **최소 3가지를 바꾼다.**
1. 도입 방식: 숫자 결론 / 실제 상황 장면 / 흔한 오해 반박 / 질문 하나 / 제도 변경 소식. 직전 2편과 같은 방식 금지.
2. 구성 순서: 표 먼저 / 설명 먼저 / 사례 하나를 끝까지 따라가기 / 구간별 비교 / 질문-답 여러 개.
3. 소제목 개수(3~6)와 이름. "확인할 것", "계산 전에 확인할 것" 같은 이름을 연속으로 쓰지 않는다.
4. 표 개수(0~3)와 위치. 표가 꼭 필요한 글만 표를 쓴다.
5. 끝맺음: 체크리스트 / 한 문장 판단 / 다음 계산 안내 / 없음.
6. 분량: 주제에 따라 1,500자 글도 3,500자 글도 있어야 한다. 매번 비슷한 길이 금지.
연봉 실수령 시리즈처럼 같은 계산기를 여러 번 쓰면 특히 주의: 같은 문장 골격에 숫자만 바꾼 글은 구글이 "대규모 콘텐츠 남용"으로 본다. 축이 다르면 글의 질문 자체가 달라야 한다.

### 11-4. 쓰는 방법
1. 먼저 그 검색어로 들어온 사람의 **진짜 질문 1개**를 한 문장으로 적는다(예: "연봉 6000이면 월급날 통장에 얼마 찍히나, 부양가족 있으면 달라지나").
2. 그 질문에 답하는 데 필요한 숫자를 계산기로 뽑는다. 숫자를 보고 나서 구성을 정한다(구성을 먼저 정하고 숫자를 채우지 않는다).
3. 다 쓴 뒤 **소리 내 읽듯 다시 읽고**, 사람이 안 할 말은 지운다. 같은 내용을 두 번 말하는 문장은 지운다.
