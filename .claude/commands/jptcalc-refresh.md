# 제이퍼 정책 수치 최신화 스킬

## 목적

jptcalc.kr의 **세율·보험요율·기준값**을 정기 점검해 항상 최신으로 유지. 계산기 사이트는 수치 정확성 = 사용자 신뢰 = 검색 노출 직결. 블로그 글뿐 아니라 **계산기 페이지(/calc/**) HTML 안에 박힌 상수까지** 점검 대상.

## 마스터 데이터 파일

`/home/tjd618/jptcalc/data-points.md`

각 항목 구조:
- 항목명
- 현재 값
- 적용 시기 (예: 2026년)
- 공식 출처 URL
- 마지막 확인일
- 변동 주기 (연 1회 / 분기 / 한은 결정 시 / 법 개정 시 등)
- 검색 패턴 (영향 페이지 자동 식별용, 여러 표기 형태 포함)
- 영향 페이지 (블로그 + 계산기 경로 둘 다)

## 실행 원칙

- 사용자 명시 없으면 **5~7개 항목** 점검
- **마지막 확인일 오래된 순** + **변동 주기 도래 항목 우선**
- 공식 출처는 부모 Claude가 **직접 WebFetch**로 검증
- 변경 발견 시 **사용자 승인 후** 일괄 수정
- 마스터 파일이 비어 있거나 부족하면 첫 가동에서 시드 항목 채움

## 가동 절차

### Step 0: 마스터 파일 확인

`/home/tjd618/jptcalc/data-points.md` 존재 확인.
- 없으면: 시드 리스트로 골격 생성 후 사용자에게 보고
- 있으면: 영향 페이지 매핑 최신화 (각 검색 패턴을 blog/posts + calc/** 에 grep)

### Step 1: 점검 항목 선정

```
1. data-points.md 읽기
2. 모든 항목의 "마지막 확인일" 추출
3. 오래된 순으로 정렬
4. 변동 주기 도래 항목(예: 12~1월의 보험요율, 7월의 A값) 가중치 추가
5. 상위 5~7개 픽업 → 사용자에게 알림
```

### Step 2: 공식 출처 WebFetch 검증

각 항목에 대해:
1. `공식 출처` URL을 WebFetch
2. 페이지에서 현재 값 추출 시도
3. 추출 성공: 마스터 값과 비교
4. 추출 실패 (WAF·동적 페이지): 사용자에게 수동 확인 요청

### Step 3: 변경 발견 시 영향 페이지 식별

값이 변경된 항목에 대해:
1. `검색 패턴`을 `/home/tjd618/jptcalc/blog/posts/` 와 `/home/tjd618/jptcalc/calc/` 에 grep
2. 매칭된 파일 경로 목록 추출
3. 각 파일에서 매칭된 줄 번호와 컨텍스트 표시

### Step 4: 사용자 보고 + 승인 대기

```
## 변경 발견 항목

### 1. 2026년 최저임금
- 옛 값: 시급 9,860원 (2024년)
- 새 값: 시급 10,030원 (2026년 적용)
- 출처: 고용노동부 공고
- 영향 페이지: 8건
  - blog/posts/minimum-wage-2026.html (3곳)
  - blog/posts/hourly-wage-guide.html (2곳)
  - calc/salary/hourly-wage/index.html (상수 1곳)
  - ...

### 2. ...

이대로 일괄 수정할까요?
```

### Step 5: 일괄 수정 (승인 후)

각 영향 파일에 대해:
1. 매칭된 모든 위치 수정
2. 시점 표현 업데이트 ("2025년 기준" → "2026년 기준")
3. JSON-LD `dateModified` 필드 있으면 오늘 날짜로
4. 계산기 HTML 안의 JS 상수도 수정 (예: `const MIN_WAGE = 10030;`)
5. 누락 방지: 같은 파일에 옛 값이 남아있는지 재grep

### Step 6: 마스터 리스트 업데이트

`data-points.md`:
- 변경된 항목의 `현재 값` 갱신
- 모든 점검 항목의 `마지막 확인일` → 오늘
- 변경 이력 섹션 추가:

```markdown
### 2026-04-29
- 점검: 7개 (최저임금, 건강보험요율, ...)
- 변경: 2건 (최저임금 → 10,030원, 건강보험 → 7.15%)
- 영향 파일 수정: 14개
```

## 주의사항

- **수치 형식 다양성**: "10,030원" / "1만30원" / "시급 1만원" 등 표기 다름. 검색 패턴은 여러 형태 포함 필수
- **문맥 검증**: 같은 숫자가 다른 의미일 수 있음. 수정 전 컨텍스트 확인
- **계산기 JS 상수**: HTML 안 `<script>` 블록의 변수도 잊지 말 것 (ex: 누진공제 배열, 요율 상수)
- **공시지가·기준중위소득 같은 변동 큰 값**: 글에서 "2026년 기준"으로 명시되어 있어야 안전
- **카테고리 우선순위**: tax > finance > pension-welfare > baby(정책수치) > salary > realestate > auto > health/date/pet/ai
- **자동차(auto) 점검 포인트** (data-points §9): 자동차세 연납공제율(1월·최고리스크)·개소세율(7/1 분기)·전기차 보조금/취득세 감면(1월·연말)·잔가율표(1월)·충전요금(개편 시). 자동차세·취득세=지방세라 realestate 다음 우선순위. 지자체 보조금·공채는 직접입력/면책이라 점검 대상 아님
- **출산·육아(baby) 점검 포인트** (data-points §10): 부모급여(0세100/1세50만)·아동수당(만9세·월10만)·첫만남이용권(200/300만)·가정양육수당(일반10/농어촌15.6·12.9·10/장애아20·10만) = **매년 1월 복지로·보건복지부 예산 시행 시 일제 점검**. 육아휴직급여(일반 1~3개월100%상한250만/4~6개월200/7~12개월80%160·하한70만 + 6+6 250·250·300·350·400·450만)=**고용노동부 고시 변동 잦음(2025 대폭 개편)**, 연초+수시(nodong.kr·고용24). ⚠️아동수당 연령 확대(8→9세) 같은 제도 변경 주시. 순수 날짜계산기(배란일·출산예정일·아기개월수)는 정책상수 없어 refresh 면제. 지자체 출산장려금은 직접입력/별도라 점검 대상 아님
- **배포 금지**: 수정만 하고 rsync는 사용자가 직접 (사용자 룰)
- **불필요한 하이픈 리스트 금지**: 블로그 본문 수정 시 사용자 룰 준수

## 정기 가동

- **매월 초 (1~3일) 월 1회**: 10~12개 항목 회전 점검. ~50개 항목 / 10~12 = 약 4~5달에 한 바퀴 (변동 빈도 낮은 세율·요율 특성상 충분). 월말이 아니라 **월초**인 이유: 제도는 거의 1일자 시행이라 월초 실행이 그 달 시행분을 즉시 캐치 (특히 7/1 A값)
- **매년 1월 첫째 주**: 모든 "연 1회" 항목 일제 점검 (보험요율·최저임금·간이세액표·실업급여 상하한 변경 직후) - **연중 최우선 가동**
- **매년 7월 초**: 국민연금 A값 점검 (7/1 적용 - 월초 실행이 변경 즉시 반영) + 🔴**자동차 개별소비세 7/1 정상세율 5% 복귀**(2026 한시인하 3.5% 6/30 종료) → acquisition-tax 출고시점 토글·문구 점검
- **매년 1월 (위 일제점검에 포함)**: 자동차세 연납공제율(시행령 제125조⑥)·전기차 국고보조금/차량가 구간(환경부 지침)·전기차 취득세 감면 한도(전년말 일몰)·차량 시가표준액 잔가율표(행안부 고시) 일제 점검 + **출산·육아 정책수치(부모급여·아동수당·첫만남이용권·가정양육수당) 복지로·보건복지부 예산 시행 일제 점검 + 육아휴직급여 상한·지급률 고용노동부 고시 점검(변동 잦음)**
- **육아휴직급여 고시 발표·개편 직후 (수시)**: 고용노동부 육아휴직급여 상한·지급률·6+6 특례 변경 시 즉시 점검 (nodong.kr·고용24 모니터링, 2025처럼 대폭 개편 잦음)
- **전기차 충전요금·보조금 지침 개편 발표 직후**: ev-charging 단가·ev-subsidy 국고액 즉시 점검 (ev.or.kr 모니터링)
