# 애널리틱스 일일/주간 성과 리포트

## 목적

jptcalc, bumohyetaek, lovtaro, formda 4개 사이트의 **GA4 + 서치콘솔 데이터**를 한 번에 조회해서 운영 인사이트 제공.

## 사이트별 오픈일 (컨텍스트)

| 사이트 | 오픈일 | 비고 |
|--------|--------|------|
| jptcalc | 2026-03-23 | 계산기+블로그 (네이버·ChatGPT 유입 중심) |
| bumohyetaek | 2026-04-03 | 정책/육아 정보 블로그 |
| lovtaro | 2026-04-06 | 인스타 타로 카드 |
| formda | 2026-07-08 | 문서 자동작성 도구 (Cloudflare Pages) |

**판단 기준:**
- 오픈 30일 미만 → 초기 단계, 색인/유입 적은 게 정상
- 오픈 30~90일 → 색인 본격화, 순위 변동 큼
- 오픈 90일 이상 → 안정화, 키워드 전략 유효

조언 시 오픈 일수를 고려해서 현실적 평가 제공 (예: 오픈 15일차인데 클릭 10회면 나쁘지 않음).

- 유입/조회수 변동 (전 기간 대비)
- 인기 페이지 / 인기 검색어
- **11~20위 키워드** 자동 추출 (보강 우선순위)
- **Thin Page 의심** 페이지 자동 탐지 (체류 15초 미만)
- 콘텐츠 품질 점검 (네이버 체류시간·카카오 애드핏 품질 기준 대비)

## 실행 방법

```bash
node /home/tjd618/.claude/analytics/report.mjs [period] [site]
```

### 파라미터

- `period` (선택, 기본값 `7d`):
  - `1d` — 어제 하루
  - `7d` — 최근 7일 (기본)
  - `28d` — 최근 28일 (서치콘솔 표준)
  - `30d` — 최근 30일
  - `90d` — 최근 90일
- `site` (선택, 기본 전체):
  - `jptcalc` / `bumohyetaek` / `lovtaro` / `formda`

### 예시

```bash
# 전체 사이트 7일 리포트 (기본)
node /home/tjd618/.claude/analytics/report.mjs

# 어제 하루만
node /home/tjd618/.claude/analytics/report.mjs 1d

# jptcalc만 28일
node /home/tjd618/.claude/analytics/report.mjs 28d jptcalc

# lovtaro만 30일
node /home/tjd618/.claude/analytics/report.mjs 30d lovtaro

# formda만 7일
node /home/tjd618/.claude/analytics/report.mjs 7d formda
```

### 2-1. ⚠️ 애드센스 게이트 동시 점검 (site 가 jptcalc 이거나 전체일 때 항상)

```bash
node /home/tjd618/.claude/analytics/adsense-gate.mjs
```

**왜 매번 보는가**: 2026-08-13 애드센스 4차 거절(4연속 "가치가 별로 없는 콘텐츠"). 온사이트 요인은 전수 재측정 결과 무혐의였고 진짜 원인은 구글의 사이트단위 색인 거부였다(블로그 146편 중 36편만 색인, 주간 노출 6회). 같은 날 미색인 105편을 googlebot 한정 noindex 로 격리했다. **5차 신청은 날짜가 아니라 아래 두 신호가 같이 뜰 때만 한다.** 그래서 성과 리포트를 볼 때마다 같이 확인해 시점을 놓치지 않는다.

- 게이트 1: 최근 30일 발행글 색인율 50% 이상 (2026-08-13 기준 1/6 = 17%)
- 게이트 2: GSC 주간 노출 300 이상 (2026-08-13 기준 27)

소요 1분 미만(카나리아만 검사). **전수 스캔 `check-indexing.mjs` 는 10분 넘으므로 여기서 돌리지 말 것.** 분기 1회면 충분하다.

판정별 보고:
- **두 게이트 통과** → 리포트 맨 위에 "5차 신청 가능" 을 올리고, 신청 전 `node ~/jptcalc/scripts/check-noindex-excluded.mjs` 종료코드 0 확인을 안내한다.
- **미달** → 한 줄로만 현황 전달(수치와 미충족 항목). 매번 장문으로 반복 설명하지 않는다.
- **12월 초까지 무반응** → 손절선. 구글 회복 대기를 접고 애드센스 1순위를 lovtaro 로 이전하는 검토를 제안한다(7월 PV 10,265 로 jptcalc 초과, 색인상태 미점검).

### 2-2. 📊 AI 구간표 효과 측정 (jptcalc, **2026-10 부터** 판정)

```bash
node /home/tjd618/.claude/analytics/ai-table-effect.mjs
```

**무엇을 재는가**: 2026-08-24 에 계산기 53개에 `calc-runner` 로 생성한 **검증된 구간표 55개**를 삽입했다. AI(챗지피티·퍼플렉시티·코파일럿 등)가 페이지를 읽고 **계산까지 해서 값을 가져가게** 만드는 것이 목적이었다. 그 효과를 추적한다.

- 기준선: **AI 유입 일평균 6.3세션** (2026-07-27~08-23, 28일 191세션). 6월 대비 이미 -60% 하락 중이던 상태
- 표를 넣은 53개 페이지가 AI 유입의 **53%** 를 차지하므로 측정 대상으로 적절
- 대상 페이지 목록·기준선은 `~/.claude/analytics/ai-table-pages.json`

**⚠️ 2026-10 이전에는 증감으로 성패를 판단하지 말 것.** 네이버는 수정 후 1~2개월 뒤 성숙하고 크롤러 재방문도 그만큼 걸린다. 그 전 수치는 기록용이다. 스크립트가 날짜를 보고 알아서 "관측 기간"이라고 표시한다.

**판정별 대응**:
- 🟢 기준선 +30% 이상 → 표 확대 검토 가능(단 남은 계산기 51개는 대부분 AI 가 native 로 계산하거나 룩업형이라 값어치 낮음)
- 🟡 보합 → **zero-click 구조 의심**. AI 가 계산해서 답만 가져가고 클릭은 안 하는 것. 원래 목표가 "AI 트래픽 급증"이 아니라 **인용 정확도·출처 점유**였음을 상기하고, 세션만으로 실패로 규정하지 말 것
- 🔴 기준선 미달 → 원인부터 분해(zero-click / 구글 색인거부의 AI 전이 / 외부 요인). **표를 더 늘리는 것으로 대응하지 말 것** - 템플릿 양산 위험만 커진다

**표를 늘릴 때 지켜야 할 것**(효과가 좋아 확대할 경우):
- 표는 반드시 `~/.claude/tools/calc-runner/` 의 `gen-examples.mjs` 로 **실제 계산기를 돌려** 생성한다. 손으로 쓰면 JS 와 어긋난다
- 인트로 문구는 `to-html.mjs` 가 6가지로 분산한다. 같은 문장을 전 페이지에 넣으면 템플릿 신호가 된다
- 입력이 7개 이상인 계산기(펫 월생활비·입양비용 등)는 **넣지 말 것**. 고정 가정이 대표성을 잃어 AI 가 조건 없이 인용하면 틀린 정보가 된다

### 3. 결과 해석 및 조언

스크립트 출력 그대로 사용자에게 전달하되, 다음 관점에서 **짧은 조언 2~3줄** 덧붙임:

- **Thin Page 많으면**: `/blog`로 관련 주제 보강 권고 (네이버 체류시간·애드핏 품질에 직결). 단 "Thin Page 의심"은 오탐이 잦으니 보강 전 실제 텍스트 char 수를 재고 quick-answer·카드탐색형인지 분해할 것
- **발행 속도 조언 금지 (jptcalc 한정, 애드센스 결과까지)**: 트래픽이 정체돼도 "발행을 늘리자"고 권하지 말 것. 구글 강등 원인이 대량생산이라 주7 복귀는 게이트 1을 스스로 끄는 행동이다. 주2~3 유지가 정답
- **11~20위 키워드**: `/blog` 또는 `/bolster`로 해당 키워드 보강 제안
- **체류시간 짧은 페이지**: 콘텐츠 품질 점검 필요
- **전 기간 대비 급감**: 원인 추정 (계절성/알고리즘/경쟁) 및 대응책

## 주의사항

- **credentials.json은 절대 공유/커밋 금지** (이미 `.claude/analytics/`에 저장됨)
- API 할당량은 무료 티어 내에서 충분 (일일 수백 회 호출 가능)
- 데이터는 GA4/서치콘솔 처리 지연으로 **2~3일 전 데이터까지만 안정적**
- 너무 최근 데이터(오늘, 어제)는 부분 데이터일 수 있음
