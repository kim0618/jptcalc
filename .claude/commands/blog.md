# 블로그 글 작성

## 0. 발행 요일 게이트 (다른 무엇보다 먼저 확인)

**발행 요일: 월요일 · 화요일 · 목요일 (주 3편)**

작업 시작 즉시 아래를 실행해 실제 요일을 확인한다. **절대 날짜를 보고 요일을 추측하지 말 것.**

```bash
date +"%Y-%m-%d (%a) u=%u"   # u: 1=월 2=화 3=수 4=목 5=금 6=토 7=일
```

- `u`가 **1·2·4**(월·화·목)이면 → 그대로 진행한다.
- `u`가 **3·5·6·7**(수·금·토·일)이면 → **글을 쓰지 말고 즉시 멈춰서 사용자에게 알린다.** 주제 선정도 하지 않는다.

**비발행일 알림 문구 (그대로 사용):**
> 오늘은 YYYY-MM-DD **N요일**로 블로그 발행 지정 요일(월·화·목)이 아닙니다. 그래도 작성할까요? "진행"이라고 하시면 쓰겠습니다.

사용자가 "진행", "그래도 써", "오늘 써" 등으로 **명시적으로 지시하면 작성한다.** 사용자가 요일을 이미 알고 지시한 경우(예: "수요일인데 오늘 하나 써줘")도 명시 지시로 본다. 단, 알림 없이 임의로 진행하지는 않는다.

### 왜 주 7편 → 주 3편인가 (2026-07-30 변경)
발행량 자체가 오류 공급원이었다. 편당 40개 이상의 사실 주장을 만드는데, 정확도 95%만 해도 편당 2건이 남는다. 실제로 `blog/verified-posts.md`에 기록된 검증 회차 약 80건 중 **"오류 0건"은 단 1건**이었고, 2026-07-30에는 1~3차 검증을 모두 통과한 신규 글에서 4차(법령 원문 대조)에 가서야 핵심 서사 오류가 적발됐다. 편수를 줄여 **편당 검증 깊이(법령·고시 원문까지 내려가기)를 확보하는 쪽이 총 품질에 유리하다**는 판단이다. 발행 간격이 생기는 수·금·토·일은 `/verify` 순환과 data-points 적립에 쓴다.

## 편수 원칙
- **사용자가 명시하지 않으면 반드시 1편만 작성한다.** (지정 요일 1일 = 1편)
- 사용자가 "5개", "3편" 등 명시한 경우에만 그 수를 따른다.
- 절대로 자의적으로 편수를 늘리지 않는다.
- 한 주에 월·화·목 3편을 넘겨 쓰지 않는다. 사용자가 추가를 지시하면 따르되, 주 3편을 넘긴다는 사실을 먼저 알린다.

### ⚠️ 원문 검증 의무 (2026-07-30 신설, 인용 ≠ 검증)

**기관을 "인용"하는 것과 원문과 "대조"하는 것은 다르다.** 종전 규칙은 링크·조문명을 적으면 체크가 통과됐고, 그래서 웹서치 요약만 보고 쓴 글이 "출처 있음 ✓"으로 넘어갔다. 2026-07-30 실제 사고: 웹서치 요약만으로 "동물보호법 제12조", "등록비 1만~3만원", "이사하면 변경신고 과태료"를 썼고 **1·2·3차 검증까지 전부 통과**했으나, 4차에서 `law.go.kr` 원문을 열자 셋 다 틀렸다(정답: 제15조 / 수수료 1만원은 칩값 제외라 실제 5만~9만원 / 전입신고가 주소 변경신고를 의제).

**아래 유형의 주장은 원문 확인 없이는 본문에 쓰지 않는다.**

| 주장 유형 | 반드시 볼 원문 | 웹서치만 했을 때 |
|---|---|---|
| 법률·시행령·시행규칙 조문번호, 과태료·벌칙 금액·차수 | `law.go.kr` (조문 본문, 별표 포함). API: `https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&MST=<MST>&type=XML` | **쓰지 말 것** |
| 수수료·요율·공제한도·급여 상하한 | 소관부처 고시 원문 또는 시행규칙 별표 | **쓰지 말 것** |
| **급여·세액 계산식(상한·하한이 붙는 공식)** | `law.go.kr` **조문 원문의 괄호 위치까지**. 요약 페이지는 괄호를 표시하지 않아 원리적으로 검증 불가 | **쓰지 말 것** |
| 의학·건강 기준(분류표·컷오프·목표치) | 해당 학회 진료지침 원문 또는 학회지 논문 | **쓰지 말 것** |
| 통계 수치(유병률·평균·인지율 등) | 발표기관 원 보고서. **분모가 무엇인지까지 확인** | **쓰지 말 것** |
| 정부 사업 일정(자진신고·신청기간 등) | 소관부처·지자체 공고 원문 | **쓰지 말 것** |

**구체 규칙:**
- **법정 수수료 ≠ 실제 비용.** 수수료·실비(장치·시술)·지자체 지원 자부담은 **항상 분리해 표기**한다. 조문에 "소유자가 직접 구매·지참" 류 문구가 있으면 그 수수료에는 실비가 빠져 있다는 뜻이다. 하나로 뭉쳐 "○○비용 N만원"이라 쓰지 말 것.
- **🔴 계산식은 "상한이 어디에 붙는지"를 원문에서 확인한다.** 상한·하한이 **곱하기 전 기준금액**에 붙는지 **최종 지급액**에 붙는지에 따라 답이 배 단위로 달라진다. 2026-08-04 육아기 근로시간 단축급여 글이 이 순서를 반대로 써서 정부지원금을 **2.5배 과대**(310만원 vs 실제 122.5만원) 계산했고, 값마다 출처가 있었고 셀 검산도 통과해 `/verify` 1단계가 **"이상 없음"으로 통과**시켰다. easylaw 요약은 괄호 위치를 안 보여주므로 반드시 조문 원문(`<조문단위>` 안 CDATA, 계산식은 ASCII 박스표)을 열 것.
- **`law.go.kr`은 WebFetch로 받으면 긴 법령이 잘려 실패한다. curl로 저장 후 파싱할 것.**
  ```bash
  curl -s "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=law&query=<법령명>&type=XML"        # MST 확보
  curl -s "https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&MST=<MST>&type=XML" -o law.xml  # 전문
  ```
- **시행일은 부칙에서 확인한다.** "공포 후 N개월이 경과한 날" 형태가 흔해 공포일 ≠ 시행일이고, **같은 제도에 시기가 다른 개정이 여러 건 겹쳐 있어** 혼동하기 쉽다(같은 날 "2024-07 자녀연령 확대"로 썼으나 실제는 2025-02-23이었고, 2024-07-01은 급여구간 확대라는 별개 개정이었다).
- **2차 출처(casenote.kr·lbox 등)는 구법 텍스트를 캐싱한다.** 조문 확인용으로 쓰지 말 것.
- **조문번호는 개정으로 바뀐다.** 전부개정이 있었던 법(예: 동물보호법 2023.4.27 전부개정으로 등록의무 제12조→제15조)은 구 조문번호가 인터넷에 대량 잔존한다. 조문번호는 반드시 현행 원문에서 확인한다.
- **의무의 주체·요건을 위임 관계까지 확인한다.** 본법이 "대통령령으로 정한다"고만 하면 실제 요건(월령·기한·예외)은 시행령·시행규칙에 있다. 본법 조문만 보고 요건을 단정하지 말 것.
- **통계는 분모를 확인한다.** "조절률 58.6%"가 전체 유병자 기준인지 치료자 기준인지에 따라 독자에게 전달되는 위험이 두 배 달라진다(2026-07-30 실제 오류).
- **"예정"으로 헤지하기 전에 이미 공고됐는지 검색한다.** 확정 공고를 "예정"으로 쓰면 글의 행동 권유가 무력화된다.
- 확인한 조문·고시는 **본문에 조문번호까지 적는다**(예: "시행령 별표 4 제2호 라목"). 근거 열에 "관련 법령" 같은 뭉갠 표현 금지.
- 원문을 못 찾았으면 **그 주장을 빼거나**, 빼기 어려우면 본문에 확인 한계를 명시하고 `verified-posts.md`에 "확인 필요"로 남긴다. **추정을 단정으로 쓰지 않는다.**


### 목차형 요약 리스트 (필수, 도입부 직후)
highlight-box 바로 다음에 "이 글에서 확인할 수 있는 것" 리스트를 삽입한다.
독자가 스크롤할 이유를 만들어주고, 검색 스니펫 노출 확률을 높인다.
```html
<ul style="background:#F9FAFB;padding:16px 20px 16px 36px;border-radius:10px;margin:16px 0;font-size:14px;color:#374151;line-height:1.8">
  <li>항목 1 - 핵심 수치가 포함된 구체적 내용</li>
  <li>항목 2</li>
  <li>항목 3</li>
  <li>항목 4</li>
</ul>
```
- 4~6개 항목, 각 항목에 구체 수치나 키워드 포함
- "~란?", "~정리" 같은 추상적 항목 금지. "연봉 3,000~1억 구간별 시급 환산표"처럼 구체적으로

### 반전 비교 섹션 (1개 필수)
독자의 기존 상식을 뒤집는 비교 데이터를 **반드시 1개** 포함한다. 이 섹션이 공유와 체류시간을 만든다.
- 예) "연봉 5,000만원인데 시급은 편의점 알바보다 낮을 수 있다"
- 예) "복리 연 5% 수익인데 물가+세금 빼면 실질 0%대"
- 예) "종부세보다 재산세가 더 많은 구간이 있다"
- h2 제목 패턴: "~인 줄 알았는데", "여기서 함정이 있다", "~보다 ~가 더 ~하다"
- 반드시 수치 근거를 함께 제시 (주장만 하지 않는다)

### 마무리 섹션 (필수)
- h2 제목은 "마무리" 고정하지 않고 매번 다르게 (이건 rewrite 스킬의 규칙과 동일)
- 요약 문단 **4문장 이상**
- **핵심 숫자 1개를 다시 한 번 강조** (예: "연봉 4,200만원의 실질 시급은 13,834원이었습니다")
- 계산기 활용 권유로 자연스럽게 마무리

## 자연스러운 글쓰기 (AI 티 제거)

기존 글이 전부 동일 구조/문체면 네이버·검색엔진과 카카오 애드핏의 AI 필터가 자동 생성 콘텐츠로 판단할 수 있다.
**새 글은 아래 규칙을 반드시 적용해서 글마다 다르게 쓴다.**

### 구조 다양화
- 본문 구성 순서(도입→표→시나리오→FAQ→마무리)를 **글마다 셔플**한다
  - 어떤 글은 시나리오로 시작, 어떤 글은 핵심 수치 결론부터
  - 비교표가 먼저 오는 글도 있고, 설명 후 표가 오는 글도 있어야 함
- highlight-box 위치를 고정하지 않는다. 중간에 쓰기도 하고, 아예 안 쓸 수도 있다
- FAQ 개수: **3~5개 랜덤**. 매번 4개 고정하지 않는다

### 문체 다양화
- **도입부 패턴을 5가지 이상 돌려쓴다:**
  1. 질문으로 시작: "혹시 ~해본 적 있으신가요?"
  2. 결론 먼저: "결론부터 말하면, ~입니다."
  3. 상황 묘사: "계약서에 사인하기 직전, 갑자기 ~"
  4. 통계/팩트: "2026년 기준 ~는 00만원입니다."
  5. 반전: "~라고 생각하기 쉽지만, 실제로는 ~"
- **"~정리합니다", "~알아보겠습니다" 남발 금지** - 전체 글에서 1회 이하
- 중간중간 **짧은 문장**(10자 이하)을 섞는다: "핵심은 이겁니다.", "답은 간단합니다."
- 일부 섹션에서 **필자의 판단/의견**을 넣는다: "개인적으로는 ~가 더 낫다고 봅니다"
- 독자에게 말을 거는 톤을 섞는다: "여기서 주의할 점이 하나 있는데요."

### 반복 패턴 회피
- 직전 3개 글의 도입부 패턴을 확인하고 **다른 패턴** 사용
- h2 제목 스타일도 다양하게: "~란?", "~하는 법", "~비교", "~의 진실", "왜 ~인가"
- 마무리 섹션도 항상 "마무리"가 아니라 "정리하면", "한 줄 요약", "체크리스트" 등으로

### 0. ⚠️ noindex 격리는 두 체제다. 방향이 정반대이니 섞지 말 것

**체제 A 전면차단 15편** (`robots noindex,follow`, 2026-06-29) - 구글·네이버 모두 차단 + 세 파일에서 제외. 아래 원문 참조.

**체제 B 구글한정 105편** (`googlebot noindex,follow`, 2026-08-13) - 애드센스 4차 거절 후속. 구글이 이미 색인을 거부한 블로그 105편을 **구글 시야에서만** 뺐다. 이 글들은 네이버 트래픽의 본체이므로 **sitemap·blog/index·rss 에 그대로 남겨야 한다**(체제 A와 정반대). 절대 하면 안 되는 것:

- 이 105편에 범용 `name="robots"` noindex 를 걸지 말 것. 네이버까지 죽어서 트래픽 본체가 날아간다. 반드시 `name="googlebot"` 이어야 한다.
- 이 105편을 sitemap 에서 빼지 말 것. 네이버 발견 경로다.
- **새로 쓰는 글에는 googlebot noindex 를 넣지 말 것.** 신규 글은 구글 색인 회복을 관측하는 카나리아다. 이게 막히면 5차 신청 시점을 판단할 지표 자체가 사라진다.
- 애드센스 로더(adsbygoogle)는 105편에도 **그대로 둔다**. 광고 크롤러(Mediapartners-Google)는 googlebot 토큰의 적용 대상이 아니라서 승인 시 네이버 유입에 광고가 정상 노출된다. (로더를 빼는 예외는 체제 A 15편뿐)

### 5. `/verify` 핸드오프 (필수, 발행일 안에 끝낼 것)

**발행으로 끝내지 말 것.** 발행일(월·화·목)의 정상 세트는 **`/blog` 1편 + `/verify` 2편(신규 1편 + 순환 1편)**이다(verify.md "요일 배치", 2026-07-30 blog 주3편 하향과 함께 설정됨). 결과 요약 뒤에 **이어서 `/verify`를 실행**한다. 대상 선정 로직이 "미검증 + lastmod 14일 이내"를 카테고리 무관 최우선으로 잡으므로, 방금 발행한 글이 자동으로 1순위가 된다.

**왜 명시하는가:** 이 연결은 2026-07-30부터 규칙이었지만 어느 스킬에도 "넘겨라"라고 적혀 있지 않아 **사람이 순서를 기억한다는 전제**로만 이어져 있었다. 2026-08-03 실제로 `/blog`만 돌고 `/verify`가 0편 돌았고, 그날 발행글의 조문 오류(대학교원 65세 근거를 고등교육법 제14조로 표기, 실제는 교육공무원법 §47① 단서)가 검증 없이 라이브로 나갔다. 같은 기간 미검증 백로그도 49→47편으로 거의 줄지 않아, 규칙만 있고 실행이 안 되던 상태였음이 확인됐다.

**🔴 새 조문·법령 주장을 도입한 글은 그날 2단계까지 완주할 것.** `/verify` 1단계(소넷)는 설계상 **법령 조문·과태료·수수료·의학 기준·통계·정부 일정을 판정하지 않고 "2단계 확인 필요"로 넘긴다.** 따라서 1단계만 돌리면 조문 오류는 남는다. 위 2026-08-03 오류도 1단계로는 잡히지 않았을 항목이었고, 오푸스 2단계 `law.go.kr` 원문 대조에서 적발됐다. 판단 기준은 간단하다. **이번 글에서 `data-points.md`에 새로 등재한 정책·조문이 있으면 2단계 대상**이다(등재는 이미 발행 조건이므로 자동으로 걸린다).

**2단계에서 확인할 것**: 조문번호(전부개정 이동 여부) · 별표 본문 · **판례는 심급**(1·2심과 대법원 결론이 정반대인 사건이 있다. 2026-08-03 실제로 언론 기사가 1심 기준이라 정확한 서술을 오류로 뒤집을 뻔했다) · 법정 수수료를 실제 비용으로 뭉갰는지 · 통계 분모 · "예정"이라 헤지한 일정이 이미 공고됐는지.
