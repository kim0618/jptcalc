# 블로그 글 오류 검증

## 목적

제이퍼 계산기 블로그 글의 **계산 오류·사실 오류·링크 오류**를 상시 검증. 전체 순환 후 다시 처음부터 반복한다.

## 실행 원칙

- 사용자가 명시하지 않으면 **하루 3편** 검증
- **신규/편집 글 최우선 → 그다음 우선순위 × 최신순**으로 대상 선정
- **병렬 Explore subagent 3개**로 교차 검증 (자기검증 편향 차단)
- 발견된 오류는 부모 Claude가 **직접 재계산 후 수정**
- 검증 완료 후 `verified-posts.md`에 기록해 재검증 방지

### 왜 신규 글 최우선인가 (2026-06-17 정책 변경)
오류는 거의 전부 **갓 발행한 신규 글**에 몰린다(2026-06-17 배치: 신규 military-salary-guide 8건 vs 기존 글 0~1건). 이미 한 번 통과한 글은 누가 편집하지 않는 한 계산·팩트가 변하지 않아 재검증 수율이 매우 낮다. 생산(주 7편)보다 검증 용량(주 21편)이 3배라, 카테고리 순환만 돌면 깨끗한 옛 글을 재검사하는 데 시간을 낭비하고 신규 글(특히 P3 카테고리)이 며칠 방치된다. 따라서 **미검증 신규 글을 카테고리 우선순위보다 먼저** 잡는다.

### Step 4: 선정 순서 (신규 우선 → 카테고리 우선순위)

**먼저 "신규/편집 글"을 골라낸다.** 미검증(verified-posts.md에 없음) 글 중 **lastmod가 최근 14일 이내**인 글 = 갓 발행했거나 최근 편집(meta-optimize·rewrite 포함)된 글. 이들을 **카테고리 무관 lastmod 최신순으로 최우선** 배치한다. 신규 글이 3편 이상이면 그날은 신규 글만으로 채운다.

신규 글로 3편이 안 차면, 나머지 미검증 글을 아래 카테고리 우선순위로 채운다.

| 순위 | 카테고리 (category 값) | 이유 |
|------|----------------------|------|
| P1 | tax, finance, pension-welfare, salary | 세율·공제·복리 계산 오류 리스크 최고 |
| P2 | health | 의료 면책 리스크 |
| P3 | realestate, pet, date, ai | 상대적 저위험 |

각 순위 내에서 lastmod 최신순. P1 소진 후 P2, P3.

선정 결과를 알릴 때 각 글이 **신규(🆕)인지 순환(🔁)인지** 표기한다.

## 검증 절차

### Step 1: 3개 글 병렬 검증 (Explore subagent 3개)

각 subagent에게 **한 개의 글 파일 경로 + 아래 전체 검증 항목**을 지시. subagent는 오류만 보고하고 **수정은 하지 말 것**.

**A. 수치 계산 정확성 (가장 중요)**
- 모든 수식 직접 재계산: 복리 FV/PV, 세금 누진공제, 물가 반영 현가, 퇴직소득세 이연 등
- 시나리오별 납부세액·실수령액·실효세율 검증
- 비교표 내 각 셀의 수치 정합성
- 1~2% 오차는 OK, 10%+ 오차는 오류 보고
- **특히 주의:** 연복리 vs 월복리, 0% 가정 누락, 누진공제 빠뜨림

**B. 법률·제도 팩트**
- 세율표, 공제 한도, 법정 한도 (상증세법, 소득세법, 국민연금법, 건강보험법, 근로기준법)
- 자주 틀리는 것: 배우자 공제 최소 5억 규정, 연금소득세 나이별 세율, 퇴직소득세 이연율(60/70%), 연금소득공제 공식, 1,500만원 기준
- 2026년 기준 최신성 (개정 반영 여부)
- **⚠️ 오탐 금지 - 의도적 값 확인**: 연간 개정 정부수치(국민연금 A값·최저임금·기준소득월액 등)를 "stale/구값 오류"로 플래그하기 전에 **반드시 `data-points.md`를 먼저 확인**한다. jptcalc-refresh가 특정 구값을 의도적으로 유지하기로 결정한 경우가 있다(예: **국민연금 블로그 6편의 A값 309만원은 2025.7~2026.6 기준으로 의도 유지 - stale 아님**, data-points.md §2.2/§748. 계산기는 2026.7 신값 A_VALUE=3193511이나 블로그는 40years 표 재계산 부담으로 2025 기준 유지 결정). refresh가 이미 판단한 사안을 verify에서 되열어 마이그레이션하지 말 것.

**C. 시의성**
- 오늘 날짜 기준 3개월 이상 미래 이벤트 주제 금지
- 이미 지난 이벤트를 "올해" 기준으로 쓰기 금지

**D. JSON-LD ↔ HTML 정합성**
- Article JSON-LD의 headline·description = head의 title·meta description
- FAQPage JSON-LD의 각 Q&A = 본문 faq-item의 Q&A (문장 단위 일치)

**E. 링크·파일 실존**
- `<a href="../posts/XXX.html">` → /home/tjd618/jptcalc/blog/posts/XXX.html 실제 존재 (ls 확인)
- CTA `../../calc/XXX/` → /home/tjd618/jptcalc/calc/XXX/ 실제 폴더 존재
- 부모혜택 `bumohyetaek.kr/guide/XXX` → /home/tjd618/bumohyetaek/src/data/articles/*/XXX.ts 존재

**F. 금지어·글자수·구조**
- em dash(—), "계산기으로", "공인인증서" 포함 금지
- **글자수는 반드시 `node scripts/count-chars.mjs blog/posts/파일.html` 로 측정** (실제 본문 순수 텍스트, head·script·style 제외). 4,000자 미만이면 thin으로 보강 권고, 6,000자 이상이면 양호. ⚠️ 옛 `sed 's/<[^>]*>//g' \| wc -c` 는 CSS/JS를 포함하고 바이트를 세서 실제의 2~4배로 부풀려지므로 절대 쓰지 말 것("15,000자" 기준은 이 착시에서 나온 허수였고, 실측 139편 중앙값은 6,176자). subagent에게도 이 스크립트로 재도록 지시할 것.
- 비교표 2개 이상, FAQ 3~5개(답변 4문장 이상), SVG 1개, 시나리오 3~4개

**G. 면책·YMYL 신뢰 점검**
- 모든 글: `blog-review-footer.js` 로드 여부 확인 (`<script src="/assets/blog-review-footer.js">` 또는 `../../assets/blog-review-footer.js`). 로드되면 면책 문구 자동 생성 → 통과. 없을 때만 본문 내 면책 텍스트 직접 확인
- 금융·투자 글: 본문 내 "참고용", "전문가 상의" 등 교육 목적 명시 여부 추가 확인
- 지나치게 단정적인 의료/법률/투자 조언 ("반드시 OO하면 낫는다" 등)

**H. 서술 ↔ 자기 데이터 정합성 (2026-07-28 신설, 셀별 검산으로는 안 잡히는 유형)**

A는 "각 셀이 맞나"를 보지만, **글이 주장하는 방향·크기 비교가 그 글 자신의 숫자에 의해 반박되는 경우**는 A를 100% 통과하고도 살아남는다. 실제 사례(2026-07-28): moving-day-guide FAQ가 "용달·셀프이사는 손없는날 할증이 상대적으로 작다"고 서술했으나 같은 글의 사례를 계산하면 용달 23.7% > 포장이사 20.0%로 정반대였음. 표의 모든 셀은 정확했다.

- **주장문 추출 → 인접 데이터로 반증 시도**: "~일수록 커진다/작아진다", "두 배", "절반", "가장 ~하다", "A보다 B가 ~", "오히려" 가 들어간 문장을 전부 뽑아, 그 주장을 뒷받침한다고 지목된 표·시나리오 숫자로 **직접 계산해 방향과 크기를 확인**한다. 방향이 반대거나 단조성이 없으면 오류.
- **제목·메타에 박힌 수치가 본문 표와 일치하는지**: 제목이 "2.2~2.6%"인데 표가 2.6~2.7%면 제목 쪽을 고쳐야 한다(실제 발생).
- **중복 등장 수치 전수 대조**: 한 편 안에서 2회 이상 나오는 숫자(도입부·표·요약·highlight-box·FAQ·메타·SVG 라벨)를 모아 서로 어긋나는 쌍을 찾는다. 수정 이력이 있는 글일수록 다운스트림이 stale하다.
- **파생 주장 재계산**: "A−B=C", "N% 저렴", "N배", "월 환산" 은 인쇄된 숫자로 다시 계산한다(예: 210÷12=17.5인데 "약 17만원"으로 표기).
- **시나리오 ↔ 표 밴드 정합**: 시나리오 금액이 같은 글의 기준표 구간을 벗어나면, 벗어날 만한 단서(장거리·차량 크기 등)가 **표에도** 명시돼 있는지 본다. 본문에만 있으면 독자에겐 모순으로 보인다.
- **시점 의존 계산**: 인물의 나이·연도로부터 "그 사람이 실제로 그 행동을 하는 해"를 먼저 확정하고, 그 해의 요율·기준값을 적용했는지 본다(실제 발생: 40세가 45세에 시작하는 납부를 현재 연도 요율로 계산).

**I. SVG 인포그래픽 정합성 (2026-07-28 신설)**
- **막대 길이 = 데이터 비례**: 각 막대의 `width`를 값으로 나눠 축척(px/단위)이 전 막대 동일한지 확인. 실제 발생: 3개월 비교 차트에서 한 달만 축척이 달라 글의 핵심 논점("8월만 7일")을 그림이 부정.
- **캡션·라벨 넘침**: 한글 11px ≒ 문자당 약 10.45px. `x + 글자수 × font-size × 0.95 > viewBox 폭` 이면 브라우저에서 잘린다. 캡션을 늘린 수정 뒤 특히 잘 생긴다 → 넘치면 2줄 분리 + viewBox 높이 확장.
- 막대 끝 값 라벨의 x좌표도 같은 식으로 검사(`text-anchor="end"` 는 제외).
- SVG 안의 수치가 본문 표와 일치하는지.

- subagent는 Explore(read-only) 사용해 임의 파일 수정 방지
- 모든 계산은 부모 Claude가 **직접 Bash로 재계산**. subagent 수치 그대로 신뢰 금지
- `/blog` 스킬로 새 글이 추가되면 자동으로 다음 검증 대상에 포함됨 (verified-posts.md에 없으므로)
- 검증 중 HTML 구조·스타일 개선은 하지 말 것. 사실·수치·링크 오류만 수정
- 글 한 편 수정으로 index.html·sitemap.xml이 영향받으면 안 되지만, 제목·desc 변경 시에는 index.html 카드 텍스트도 동기화

```bash
python3 -c "import json,datetime; logs=json.load(open('/home/tjd618/skill-log.json')); now=datetime.datetime.now(); logs.insert(0,{'date':now.strftime('%Y-%m-%d'),'time':now.strftime('%H:%M'),'project':'jptcalc','skill':'verify'}); open('/home/tjd618/skill-log.json','w').write(json.dumps(logs,ensure_ascii=False,indent=2))"
```
