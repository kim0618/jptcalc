# 배포 정책

## Claude의 역할 범위

- 파일 생성/수정 (HTML, CSS, JS)
- `/blog/index.html`, `sitemap.xml`, `rss.xml` 업데이트
- **여기까지가 끝**

## Claude가 절대 실행하지 않는 것

```bash
# 아래 명령어 실행 금지
rsync -avz ...
ssh ...
scp ...
```

배포(rsync)는 사용자가 직접 수행. Claude는 배포 명령어를 제안하거나 실행하지 않음.

## 작업 완료 보고 형식

파일 생성/수정 완료 후:
- 생성/수정한 파일 목록 나열
- "빌드 완료. 배포는 직접 진행해 주세요." 로 마무리
- rsync 명령어 출력 금지

## 배포 범위: 허용 목록만 올린다 (2026-10-21 개정)

2026-10-21 점검에서 운영 사이트가 `.git` 전체, `.claude`, 내부 기록 `.md`, `serve.py`를 공개 주소로 내주고 있었다. 저장소 루트를 웹 루트에 통째로 동기화하고, 웹 서버가 점 경로·`.md`를 막지 않았기 때문이다.

- **필터 없이 배포 금지.** 배포는 저장소 루트의 `.deploy-filter`(허용 목록)를 merge 필터로 지정해서만 한다. 함께 쓰는 옵션: 삭제 동기화 + **제외 대상까지 삭제**(`--delete-excluded`) + 빈 폴더 정리. 제외 대상까지 삭제를 빼면 이미 서버에 올라간 `.git`·내부 문서가 그대로 남는다.
- 공개 허용 형식: html, css, js, `assets/` 아래 json, 이미지(png·webp·jpg·gif·svg·ico), webmanifest, 웹 글꼴, 루트의 sitemap.xml·rss.xml·robots.txt·ads.txt·llms.txt. 그 밖의 형식이 공개돼야 하면 `.deploy-filter`를 먼저 고친다.
- 항상 제외: 점으로 시작하는 모든 것, `design/`, `scripts/`, `__pycache__/`, `node_modules/`, `*.md`, `*.py`, `*.mjs`, `*.sh`, `*.csv`.
- 서버 `/.well-known/`은 필터의 보호 규칙(P)으로 지우지 않는다(인증서 갱신).
- 웹 서버에도 같은 차단 규칙(점 경로·내부 형식·작업 폴더 404)을 둔다. 배포 실수가 있어도 공개되지 않게 하는 이중 방어다.
- **배포 전 로컬 확인**: 필터를 로컬 임시 폴더에 먼저 적용해 결과에 내부 파일이 0개인지, 페이지가 참조하는 파일이 빠지지 않았는지 본다(점검 스크립트는 저장소 밖 관리).
- **배포 후 확인**: 외부 GET 점검(차단 대상 404, 공개 유지 200)을 배포할 때마다 1회.
- 공개 저장소 원격 주소·서버 주소·계정은 저장소 문서에 적지 않는다.
