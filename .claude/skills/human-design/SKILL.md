# Human-made Design Skill

목표: "AI가 만든 것 같다"는 인상을 주는 기본값을 전부 피하고, 한 사람의 디자이너가 명확한 취향으로 결정한 것처럼 보이게 만든다.

## 0. 코드 작성 전 반드시 할 것 (생략 금지)

1. `design/brief.md`를 먼저 작성하고 사용자에게 보여준다.
   - 브랜드 한 줄 정의, 타깃, 무드 키워드 3개
   - 레퍼런스 2~3개 (실존 사이트/브랜드, 무엇을 가져올지 구체적으로)
   - 선택한 미적 방향 1개 (예: 에디토리얼 / 스위스 그리드 / 따뜻한 미니멀 / 브루탈리즘 / 럭셔리 다크)
   - 이 방향에서 "하지 않을 것" 3개
2. `design/tokens.css`에 토큰을 먼저 정의한다. 컴포넌트에서 하드코딩 색·px 금지.
3. `design/` 폴더에 사용자가 넣은 레퍼런스 스크린샷이 있으면 먼저 Read로 보고 공통점을 brief에 적는다.

## 1. 금지 목록 (AI 티의 주범)

- 보라/파랑 → 핑크 그라데이션 배경, 그라데이션 텍스트
- Inter, Roboto, 시스템 폰트만 쓰는 구성
- 모든 요소에 rounded-2xl + shadow-lg 카드
- 아이콘 + 제목 + 설명 3열 기능 카드 그리드 (히어로 바로 아래 고정 패턴)
- 이모지를 아이콘 대신 사용
- "Unlock", "Seamless", "Elevate", "Empower" 같은 마케팅 상투어, "🚀 Get Started"
- 모든 섹션 중앙 정렬 + 같은 패딩 반복
- 의미 없는 glassmorphism, 블롭 배경, 떠다니는 장식 도형
- 가짜 통계("10,000+ users"), 가짜 후기
- 모든 버튼 hover에 scale 애니메이션

## 2. 사람처럼 보이게 하는 규칙

### 타이포그래피 (가장 중요)
- 폰트는 최대 2종. 헤드라인용 개성 있는 폰트 1개 + 본문 1개.
  - 한국어: 본문 Pretendard/SUIT, 헤드라인은 명조 계열(Noto Serif KR, MaruBuri) 또는 개성 있는 고딕 중 택1
- 타입 스케일은 비율로 정한다(예: 1.25 또는 1.333). 임의 숫자 금지.
- 헤드라인은 크게, 과감하게. 본문과의 크기 대비를 확실히(최소 2.5배 이상).
- letter-spacing: 큰 헤드라인은 약간 좁게(-0.02em), 대문자 라벨은 넓게(0.08em).
- 본문 행 길이 60~75자, line-height 1.6~1.75(한국어).

### 색
- 뉴트럴 1세트(완전한 #000/#fff 대신 살짝 톤 있는 off-black/off-white) + 메인 1색 + 포인트 1색.
- 포인트 색은 화면의 5% 이하. CTA와 핵심 강조에만.
- 회색은 브랜드 색 쪽으로 약간 기울인다(차가운/따뜻한 회색 중 하나로 통일).

### 레이아웃
- 12컬럼 그리드를 쓰되 일부러 비대칭 배치를 섞는다(7:5, 왼쪽 정렬 헤드라인 + 오른쪽 여백).
- 섹션마다 리듬을 다르게: 넓은 여백 섹션 → 촘촘한 정보 섹션 → 풀블리드 이미지.
- 여백은 토큰 스케일(4/8 기반)만 사용하되, 섹션 간 여백은 과하다 싶을 만큼 크게.
- 카드 대신 구분선, 여백, 타이포 위계로 그룹을 나눌 수 있는지 먼저 검토.

### 디테일 (사람이 신경 쓴 흔적)
- 라운드 값은 한 가지 체계로 통일(예: 0 / 4 / 8만 사용). 직각 디자인도 적극 고려.
- 그림자는 쓰면 1~2단계만, 아주 옅게.
- 숫자에는 `font-variant-numeric: tabular-nums`.
- 실제 콘텐츠처럼 보이는 구체적 카피를 쓴다. Lorem ipsum, "Feature 1" 금지.
- 아이콘은 한 세트(lucide 등)만, stroke 두께 통일, 꼭 필요한 곳에만.
- 모션은 절제: 150~250ms, ease-out, 진입 애니메이션은 페이지당 1~2곳.
- 포커스 상태, 빈 상태, 로딩 상태, 에러 상태까지 디자인한다.

## 3. 작업 순서

1. brief + tokens 작성 → 사용자 확인
2. 가장 중요한 화면 1개만 먼저 구현
3. 시각 검증 (아래 4번)
4. 통과 후 나머지 화면 확장

## 4. 시각 검증 루프 (필수)

브라우저 도구(Playwright MCP 등)가 있으면:
1. 개발 서버를 띄우고 데스크톱(1440px) / 모바일(390px) 스크린샷을 찍는다.
2. 스크린샷을 직접 보고 아래 체크리스트로 스스로 채점한다.
3. 걸리는 항목을 고친 뒤 다시 찍는다. 최소 2회 반복.

### 체크리스트
- [ ] 금지 목록 항목이 하나라도 보이는가?
- [ ] 3초 안에 가장 중요한 요소 1개가 눈에 들어오는가?
- [ ] 헤드라인/본문 크기 대비가 충분한가?
- [ ] 섹션들이 전부 같은 모양(중앙 정렬 + 카드 그리드)으로 반복되지 않는가?
- [ ] 포인트 색이 과하게 쓰이지 않았는가?
- [ ] 브랜드 이름을 가리면 어느 사이트인지 모를 정도로 평범하지 않은가?
- [ ] 모바일에서 여백과 타이포 위계가 유지되는가?

## 5. 최종 보고

변경 사항을 나열하지 말고, brief의 방향과 비교해 "어떤 결정을 왜 했는지" 3줄 이내로 보고한다.
